# 宝可梦训练师成长日记

一个给家里小朋友用的日常打卡工具：完成任务、照顾宝可梦、攒经验升级，家长在后台审核作业、设置任务。

**纯静态站点，没有服务器。** 账号和打卡记录存放在你自己的 GitHub 仓库里，并以**客户端加密**保存。部署到 GitHub Pages 后，家人打开一个网址就能用，换手机 / 平板登录同一账号即可看到同一份数据。

---

## 一、复制这个仓库，自己部署一份（5 步）

整套流程不需要买服务器、不需要装数据库，只需要一个 GitHub 账号。

### 第 1 步：复制代码到自己的账号

- 点本仓库右上角 **Fork**，复制一份到你的 GitHub 账号下；
- 或下载 ZIP，自己新建一个仓库。仓库名随意（如 `pokemon-diary`），**选 Public**（发给家人最省事，数据已加密，公开也读不到）。

> 复制的是「代码」，**数据是各存各的仓库**：你 fork 的仓库只会存你自己家的记录，和原仓库完全隔离。这就是存档唯一性的第一层保证。

### 第 2 步：开启 GitHub Pages

仓库 → **Settings** → 左侧 **Pages** → `Build and deployment` 里 Source 选 **Deploy from a branch**，Branch 选 `main`、目录选 `/(root)` → **Save**。

稍等约 1 分钟，站点地址就是 `https://<你的用户名>.github.io/<仓库名>/`。

> 仓库根目录有一个空的 `.nojekyll` 文件，**不要删**：它防止 Pages 把 `assets/` 里的资源当 Jekyll 模板处理而吞掉。

### 第 3 步：生成一个 PAT（整个流程唯一要动手的一次）

GitHub → 右上角头像 → **Settings** → **Developer settings** → **Personal access tokens** → **Tokens (classic)** → **Generate new token (classic)**：

- 勾选 `repo`（整项勾上即可）
- 生成后复制那串 `ghp_...`，**存好**

PAT 是浏览器直接读写 GitHub 仓库的凭据。它只保存在**你这台设备的浏览器里**，不会上传、不会写进代码、不会进仓库。

### 第 4 步：在 App 里填一次仓库信息

打开第 2 步的网址 → 首次会停在登录页 → **登录页顶部就是「GitHub 同步设置」卡片**（未配置时自动置顶），注册前先在这里告诉 App 往哪个仓库存：

1. 填 4 项：仓库所有者（你的 GitHub 用户名）、仓库名、分支（`main`）、访问令牌（第 3 步的 PAT）；
2. 点「**保存设置**」——**先验证、通过后才保存**：成功会提示「连接成功」并自动出现「第二步：登录或创建家庭账号」，失败会显示具体原因（401/404/网络）、配置不落盘、保持展开让你就地改，**不需要再单独点「测试连接」**。没验证通过之前不会显示登录 / 注册入口；
3. 连接成功后设置卡折叠成底部的精简卡，但「**存档同步**」按钮仍然在，随时可手动同步；要改 PAT 点「修改连接设置」展开。

> 登录后，「**我的数据**」页只显示**精简同步卡**（存档同步按钮 + 状态 + 规则），**不含 owner / repo / PAT**；完整的连接设置（改仓库、改令牌）只在**家长后台「设置」**页，需家长密码才能进 —— 避免孩子误改。

> **每台设备填一次**。之后孩子平板、家长手机各自填一次即可；不想每台都生成的，可以共用同一个 PAT，也可以在 GitHub 上随时撤销重建。

> **首次打开的顺序：配置仓库 → 注册 / 登录账号 → 新手引导（选第一只宝可梦）→ 问一次要不要放到手机桌面。** 未配置、未登录、或云端数据还没拉完时，不会弹出新手引导；这是为了让选择结果直接写进你的账号存档，不会覆盖已有记录。已有账号登录后也不会再弹。**注册成功后直接进入应用**，不会再要求用刚注册的账号重新登录一次。
>
> 手机桌面图标：首登结束第一次进「今日日程」会主动问一次。安卓 Chrome 会弹出**系统安装确认**，同意后桌面直接出现精灵球图标；iPhone / iPad 的 Safari 不允许网页自动加图标，弹窗会给「分享 → 添加到主屏幕」3 步图示。以后想再看步骤：**我的数据 → 账号 → 放到手机桌面**。

#### 存档是怎么保存的（App 内「存档保存规则」同款说明）

| 时机 | 行为 |
|---|---|
| 打卡 / 任何改动 | **静默 20 秒**后上传（连续操作合并成一次；最多等 60 秒；切到后台或关页面立即补传） |
| **关键步骤** | **立即上传，不等 20 秒**：选宝可梦 / 完成新手引导 / 捕捉 / 战斗结算 / 任务打卡 / 解锁新档位。换设备不会重来一遍 |
| 数据没变化 | **不写仓库**，不产生多余 commit |
| 打开页面 | 自动拉取一次云端；之后**每 5 分钟**再自动拉取 |
| 断网 | 照常打卡，联网后自动补传 |
| 多设备同时改 | 按存档里的「最后修改时间」取最新一份 |
| 每次真正上传 | 留一条 commit 用于回溯 |
| 文件会不会越存越多 | **不会**。一个账号永远只有 `accounts/xxx.json` + `saves/xxx.json` 两个文件，都是覆盖写；只有 commit 历史会增长，所以才做了节流和内容去重 |
| 作业照片 | 只存这台设备，**不进仓库**（换设备看不到照片） |
| 点「存档同步」 | 立刻上传 + 拉取一次，并回报结果 |

### 第 5 步：注册家庭账号，开始用

- 登录 / 注册在**同一张卡片的两个页签**里：默认「登录账号」，第一次使用点右上角「**账号注册**」；
- 注册只需填**孩子昵称 + 小孩密码 + 家长密码**。完成后弹窗会给出**三种都能登录的账号名**，抄下来即可：
  - **昵称**（如 `小明`）—— 最好记；
  - **短码**（如 `a1b2c3`）—— 6 位随机码；
  - **完整账号码**（如 `小明-a1b2c3`）—— 昵称 + 短码，最保险。
  - 同名账号靠密码自动匹配；旧版本注册的老账号用完整账号码照常登录，**不需要迁移**。
- 设两个密码：**小孩密码**（进打卡页）和**家长密码**（进管理后台）。输哪个密码就进哪个界面，不用选角色；
- **注册成功直接进入应用**，云端拉取完成后弹「欢迎来到宝可梦世界」选第一只宝可梦；
- 孩子忘密码 → 家长进后台「账号与密码」直接重置；**家长密码务必记牢**（见下方安全说明）。

## 二、存档唯一性是怎么保证的

因为仓库是 Public 的，这里用了四层机制，确保记录唯一、不串号、不被别人读取或覆盖：

| 层 | 机制 | 解决什么 |
|---|---|---|
| 1. 仓库隔离 | 每人 fork 自己的仓库 + 自己的 PAT | 别人写不进你的仓库，物理上就是各存各的 |
| 2. 随机账号码 | 注册时用密码学安全随机数生成 6 位后缀（`crypto.getRandomValues`），并检测撞号重试 | 单仓库内多账号也不会重名 / 串号；昵称、短码、完整账号码三种都能登录，靠密码消歧 |
| 3. 一账号一文件 | `accounts/{账号码}.json`、`saves/{账号码}.json`，写入时带 `sha`（GitHub Contents API 的乐观锁） | 跨设备同一账号只有一份存档；并发写入会冲突重试，不互相覆盖 |
| 4. 客户端加密 | 存档用 **AES-GCM** 加密，密钥由登录密码经 **PBKDF2-SHA256（10 万次）** 派生；仓库里只有密文信封 `{iv, ct}` | 仓库公开也读不到打卡内容；别人拿到密文也无法伪造记录 |

**关于第 4 层的具体设计**（开发者可看 `js/github.js` 的 `APP.cipher`、`js/auth.js`）：

- 注册时随机生成一把**存档主密钥**（vault key），分别用小孩密码、家长密码各自包裹一份，存进 `accounts/{id}.json`；
- 登录时用输入的密码试着解开包裹，解开哪个就是哪个角色，同时拿到同一把主密钥 → 两个角色看到的是同一份数据；
- 改家长密码 / 重置小孩密码 = 用新密码重新包裹**同一把主密钥**，所以**不用重新加密整份存档、数据不受影响**；
- 跨设备同步：本地 `localStorage` 只当缓存，云端 `saves/{id}.json` 是唯一权威副本，按 `savedAt` 做最后写入者胜出的合并。

## 三、安全说明与已知限制（请务必先读）

- ⚠️ **家长密码 + 账号码都丢失 = 数据无法恢复。** 加密密钥来自密码，没有服务器、没有找回通道，任何人（包括开发者）都无法帮你解出密文。请抄下账号码、牢记家长密码。小孩密码忘了可以重置。
- **PAT 权限**：classic token 勾 `repo`。它只存在本机浏览器 `localStorage`，不进仓库。换设备、清浏览器数据后需重填。担心泄露可在 GitHub 撤销后重新生成。
- **照片暂不跨设备**：v1 里作业照片只存在本机浏览器（IndexedDB），不上传仓库（避免单个文件超过 API 的 1MB 限制）。换设备看到的记录里有打卡状态，但照片不跟过去。
- **必须用 https 或 localhost 打开**：Web Crypto 加密只在安全上下文可用。直接双击 `index.html`（`file://`）会导致注册 / 登录失败。
- **站点本身公开无妨**：Pages 上的代码、图片、音效都是公开的；私密的只有你的打卡数据，而它是密文。

## 五、后续修 bug / 加功能，怎么推送到 GitHub

改完本地文件后，有 3 种方式，**推荐第 1 种**：

### 方式 1：双击 `更新推送.bat`（最省事）

在项目根目录双击即可自动完成 **`node build.js` 重新生成 `index.html`** → `git add` → `commit` → **`git pull --rebase`** → `push`。也可以带一句说明：

```
更新推送.bat "修复打卡重复计数"
```

脚本会自己找 Node.js（PATH 或常见安装路径）；万一这台电脑没装 Node，会打印醒目提示并跳过重建，直接推送现有的 `index.html`——此时如果你刚改过 `js/`，请先装 Node.js，或让 AI 帮你重新生成一次，否则线上还是旧代码。

> **为什么多了一步「同步远端」**：App 每次打卡会把加密存档直接写进同一个 GitHub 仓库，因此远端 `main` 上会不断出现 `sync: saves/...` 这样的运行时 commit。脚本会先把这些 commit 同步到本地再推送，否则 `git push` 会因「非快进」被拒绝。这些运行时 commit 只动 `accounts/` `saves/`，和代码文件不冲突。

没有改动时脚本会跳过 commit、只同步并推送，不会误报失败。推送成功后约 1 分钟，GitHub Pages 自动更新，家人刷新页面就是新版本。
（脚本内容是纯 ASCII，避免中文 Windows 命令行乱码；窗口会停留显示结果。）

### 方式 2：直接让 AI 推

把改动告诉 WorkBuddy / 其他 AI 助手，说「推送到 GitHub」，它会用你提供的 PAT 帮你提交推送。适合你不想碰命令行的情况。

### 方式 3：手动 git（懂命令行的话）

```bash
node build.js              # 关键：改过 js/ 或 css/ 就必须重建 index.html
git add -A
git commit -m "fix: 说明改了什么"
git pull --rebase origin main   # 关键：App 会在远端写 sync: 存档 commit，不同步会被拒
git push origin main
```

> **最容易踩的坑**：只改 `js/` / `css/` 然后直接 `git push`。线上加载的是**内联了全部代码的 `index.html`**，源码文件本身不会被页面读取，所以线上完全不会变。必须先 `node build.js`。

> **认证**：本仓库首次部署时 `origin` 已带凭据；如果你是 Fork 后自己 `git clone` 的，第一次推送会要求登录 GitHub（浏览器授权即可），之后由系统凭据管理器记住。若报 403 / 认证失败，多为 PAT 过期或被撤销，重新生成一个 `repo` 权限的 PAT 更新到 `origin` 地址即可。脚本里的 `-c credential.helper=` 是为了绕开部分机器上损坏的凭据助手配置。

### 推送成功，但页面还是旧的？

「代码推没推上去」和「页面看不看得见」是两件事，按顺序自查：

1. **远端到底有没有新代码**：打开 `https://github.com/<owner>/<repo>/commits/main` 确认最新 commit，再打开仓库里的 `index.html` 搜这次新加的函数名 / 文案。**所有 JS/CSS 都内联在 `index.html` 里**，改了 `js/xxx.js` 却没重新 `node build.js`，这里就搜不到，线上自然不会变。
2. **Pages 有没有构建完**：`https://api.github.com/repos/<owner>/<repo>/pages/builds/latest` 看 `status=built` 且 commit 与上一步一致；推送后约 1 分钟完成。
3. **浏览器缓存**：离线缓存对首页是「先用缓存秒开、后台拉新版」，GitHub Pages 又给 HTML 设了 `Cache-Control: max-age=600`。现在已做自动切换：
   - 每次发版把根目录 `sw.js` 里的 `var CACHE = 'pokedex-checkin-vNN'` **+1**，新 SW 接管时会清掉旧缓存，并把已打开的页面强制导航到新版；
   - 即使忘了改版本号，SW 也会用 `no-store` 绕过 10 分钟 HTTP 缓存去拿最新 HTML、比对 ETag，发现内容变了就通知页面自动刷新一次（同一版本只刷一次，不会来回抖）。
   - 想立刻看：电脑 `Ctrl+Shift+R` 硬刷新；手机清一下站点数据再打开；从桌面图标进的先关掉再开一次。
4. **已有账号的「默认任务」**：`APP.DEFAULT_TASKS` 只在新建存档 / 点「恢复默认任务」时写入，改代码不会直接改写已保存的任务。现在 `store.migrate()` 会做一次性升级：任务列表与旧版 5 项模板逐条一致时自动换成新版 8 项（打卡记录存在 `instances` 里，不会丢）；**用户自己增删改过任务则不覆盖**，需到 家长后台 → 任务管理 →「恢复默认任务」手动套用。

- [ ] 手机 / 电脑打开一次站点，确认自动切到新版

> 最省事的做法就是双击 `更新推送.bat`：它已经把「重建 → 提交 → 同步远端 → 推送」串好了。

```bash
# 然后打开 http://localhost:8800
```

> 说明：加密依赖浏览器的安全上下文，`file://` 打开会注册 / 登录失败，必须走 http(s)。

## 六、常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 注册提示「请先在…填写仓库与访问令牌」 | 每台设备首次都要在**登录页顶部**的「GitHub 同步」卡片填 4 项并保存 |
| 首次打开没弹「欢迎来到宝可梦世界」 | 这是对的：必须先配置仓库并注册 / 登录账号，云端数据拉完后才会进入新手引导；已有账号不会再弹 |
| 提示「当前环境不支持加密」 | 用了 `file://` 或 http 非 localhost 打开；改用 Pages 的 https 网址或本地预览服务器 |
| 登录一直「密码错误」 | 账号可填昵称 / 短码 / 完整账号码；注意密码大小写、全角字符。家长密码登录进后台，小孩密码进打卡页 |
| 输昵称登录提示「账号不存在」 | 确认这台设备填的是**同一个仓库**，且仓库里 `accounts/` 目录能读到该账号 |
| 测试连接返回 401 / 404 | PAT 无 `repo` 权限、已过期，或 owner / repo 名填错；保存设置时也会自动验证并给出同样提示 |
| 保存设置后找不到同步按钮 | 折叠态精简卡里仍有「存档同步」按钮；要改配置点「修改连接设置」（家长后台也可改） |
| 「我的数据」页看不到 PAT / 仓库设置 | 这是设计如此：小孩端只显示精简同步卡，完整设置在家长后台「设置」页 |
| 出现「用哪份记录继续」二选一 | 已移除。现在登录直接用账号云端那份；旧版本留在本机的记录只在家长后台「导入本机旧记录」里单向导入（云端为空才可用） |
| Pages 打开 404 | 首次构建需约 1 分钟；确认 Settings → Pages 选的是 `main` + `/(root)` |
| 换设备看不到旧数据 | 确认登录的是同一账号码，且该设备已填好同一个仓库的同步设置 |

## 七、给 AI 助手看的部署说明

如果你是把整个项目压缩包发给 AI（WorkBuddy / 豆包等）代为部署，请连同 `deploy-package/AI_DEPLOY_GUIDE.md` 一起给，并说「按里面的指南部署到 GitHub Pages」。AI 会向你索要 **PAT、仓库名、公开/私有** 三项，其余（建仓库、推送、开 Pages、取链接）全自动。
